# Как выложить работу на GitHub и сделать из неё портфолио

Репозиторий с заданием — это ваш образец работы: его можно показать на собеседовании. Поэтому он должен быть не просто «залит», а понятен постороннему человеку.

## 1. Что получится

Приватный репозиторий `radiowave-hw-<фамилия>` (латиницей). После защиты его можно сделать публичным. В нём:

```
README.md          что решали, как, что получилось (с графиками)
SOURCES.md         откуда взяты данные (см. HOWTO_sources.md)
LICENSE            лицензия на ваш код
requirements.txt   версии библиотек (для Python)
src/               программа
results/           таблицы и графики (CSV, PNG)
tests/             проверка по контрольному варианту
.github/workflows/ автоматическая проверка (по шаблону)
```

Начните с копии папки [student-template/](student-template/).

## 2. Шаги

1. Зарегистрируйтесь на github.com. Имя пользователя будет в адресе портфолио: выбирайте нейтральное.
2. Установите Git ([git-scm.com](https://git-scm.com)). Один раз настройте имя и почту:
   ```
   git config --global user.name "Имя Фамилия"
   git config --global user.email "почта"
   ```
3. Создайте на GitHub пустой репозиторий (кнопка **New**, тип **Private**, без README: он уже есть в шаблоне).
4. В папке с работой выполните:
   ```
   git init
   git add .
   git commit -m "ДЗ: первая версия"
   git branch -M main
   git remote add origin https://github.com/<ваше имя>/<репозиторий>.git
   git push -u origin main
   ```
5. Делайте **небольшие коммиты** с понятными сообщениями («Добавил расчёт r0,01», «Исправил единицы в γ_R»). По истории видно, как вы работали.
6. Откройте вкладку **Actions**: автоматическая проверка должна пройти (зелёная галочка).
7. Добавьте преподавателя: **Settings → Collaborators → Add people**, роль Read. Логин преподавателя сообщается на занятии. Без этого работу проверить нельзя.
8. Запустите `python src/solution.py --dz dzK --variant n --json results/result_dzK.json` со своим номером варианта и закоммитьте файл. Именно его читает проверка.

## 3. Чек-лист перед сдачей

- [ ] README открывается и читается за 2 минуты. Есть постановка, метод, главные результаты, графики, как запустить.
- [ ] Программа запускается чистой командой из README на новом компьютере.
- [ ] Результат для варианта 0 совпадает с ответами из задания (тест проходит).
- [ ] Свой вариант посчитан. Номер варианта указан.
- [ ] SOURCES.md заполнен: версии, разделы, проверки.
- [ ] Графики подписаны: оси, единицы, легенда.
- [ ] В репозитории нет паролей, личных данных (адрес, телефон, номер зачётки), лишних больших файлов.
- [ ] Указана лицензия.
- [ ] Раздел «Использование ИИ» заполнен (даже если ответ «не использовал»).

## 4. Что **нельзя** публиковать

- Чужие решения, ответы преподавателя, таблицу вариантов всей группы. Выкладывайте только своё.
- Тексты рекомендаций МСЭ-Р целиком (они защищены авторским правом). Ссылайтесь и цитируйте формулы по необходимости, но не копируйте документ.
- Учебные материалы курса, если у них закрытая лицензия.

## 5. Что сделает репозиторий заметным

- Один содержательный абзац в начале README: какую задачу решали и какой главный вывод.
- Графики прямо в README (картинки из `results/`).
- Раздел «Что бы я улучшил»: он показывает, что вы понимаете ограничения расчёта.
- Теги (topics) на странице репозитория: `radio-propagation`, `itu-r`, `rain-attenuation`, `python`.
- Закреплённый репозиторий в профиле (Pin).
- Короткий профиль GitHub (README профиля): кто вы, чем занимаетесь, ссылки.

## 6. Если что-то пошло не так

- `git push` отвергнут: выполните `git pull --rebase origin main` и повторите.
- Случайно выложили лишнее (пароль, личные данные): считайте, что оно уже скомпрометировано. Смените пароль и удалите файл из истории (например, `git filter-repo`) или создайте репозиторий заново.
- Не получается: спросите на консультации и покажите вывод команды целиком.

## Учёт времени

После создания репозитория из шаблона при каждом сеансе работы запускайте `start.bat` (в начале) и `stop.bat` (в конце). Подробности в README шаблона.
